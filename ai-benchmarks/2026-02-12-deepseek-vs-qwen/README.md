# DeepSeek 更新了，Function Calling 能力有提升吗？实测对比 Qwen Plus

> Soul Mate 项目实测：DeepSeek V3 旧版 vs DeepSeek V3 新版 vs Qwen Plus，29 个用例的完整 Agent 性能对比

## 背景：为什么要重新测？

2026 年 2 月 11 日，DeepSeek App 灰度推送了一次重大更新：

- **上下文窗口**：128K → 1M Token（近 10 倍提升）
- **知识截止日期**：2024 年 7 月 → 2025 年 5 月
- 多家媒体报道（IT之家、量子位、53AI 等），有用户猜测这可能是 V4 的前奏

作为一个正在开发 AI 桌面助手（Soul Mate）的开发者，我在 2 月 9 日刚做过 DeepSeek V3 和 Qwen Plus 的 Agent 性能基线测试。看到更新消息后，自然的问题是：**这次更新对 function calling / tool use 能力有没有提升？**

于是在 2 月 12 日，我用完全相同的 29 个测试用例重新跑了一轮 DeepSeek，做三方对比。

## 测试方法

### 测试框架

Soul Mate 是一个 Tauri v2 桌面应用（Rust 后端 + React 前端），内置了 3 个工具供 AI 调用：

| 工具 | 功能 |
|------|------|
| `run_command` | 执行 shell 命令（Windows cmd） |
| `read_file` | 读取文件内容 |
| `write_file` | 创建/写入文件 |

测试脚本 `test_agent.py` 完整模拟 Agent 循环：System Prompt → LLM API → 工具调用 → 结果回传 → 继续对话，直到模型给出最终回复。所有 API 调用均使用 OpenAI 兼容格式的 `/chat/completions` + `tools` 参数。

参考 [BFCL](https://gorilla.cs.berkeley.edu/blogs/8_berkeley_function_calling_leaderboard.html)（调用模式分类）和 [OSWorld](https://os-world.github.io/)（桌面 Agent 任务域），设计了 29 个用例：

## 分析：DeepSeek 的三大持续弱点

无论新旧版，DeepSeek 在 function calling 场景中始终表现出三个核心问题：

### 1. 错误/截断后反复重试

当工具返回错误或输出被截断时，DeepSeek 不信任结果，反复用不同命令尝试获取"完整"信息。

典型表现：
- C02-5 进程列表：tasklist 输出超 4000 字被截断 → 换 `wmic`、`powershell` 等反复查（5-6 轮）
- C06-2 删除不存在的文件：del 报错 → 用 dir 确认 → 再 del → 再 dir...（7-8 轮）

Qwen 的做法：截断了就基于现有信息总结，报错了就直接告知用户，2 轮搞定。

### 2. Windows cmd 知识薄弱

DeepSeek 不熟悉 Windows 命令行的高效写法。

典型表现：
- C04-3 找最大文件：不会用 `dir /O-S` 按大小排序，试了 10 种方法都不对
- C05-1 模糊搜索：不会一步 `dir *test*`，而是先 `dir`，再 `findstr`，再...（6 轮）
- C05-2 找 .lnk：同样不会 `dir *.lnk`，绕了 6 轮

Qwen 的做法：一步 `dir /O-S` 或 `dir *test*` 搞定。

### 3. GBK 编码处理差

Windows cmd 默认输出 GBK 编码，DeepSeek 看到乱码后容易误判。

典型表现：
- C07-2（新版）：尝试用 `type`、`chcp 65001`、`powershell Get-Content` 等多种方式读取中文文件，反复 10 轮触发上限
- C02-2（旧版）：read_file 读到乱码后不信任结果，额外调 2 次 run_command 验证

Qwen 的做法：read_file 读到什么就用什么，不因编码问题产生额外操作。

## 结论

### 1. DeepSeek 这次更新对 function calling 无实质改善

总分完全不变（81.5%），改善 1 处退步 4 处。App 端的更新（1M 上下文、知识库更新）可能主要影响对话能力和长文本处理，但 **function calling / tool use 的核心弱点没有修复**。

这也符合预期：上下文扩展和知识更新是基础能力升级，而 function calling 的效率更多取决于模型对工具调用策略的学习，这需要专门的训练优化。

### 2. Qwen Plus 在 Agent 场景下仍是当前最优选择

在我们的桌面 Agent 场景中：
- Qwen Plus 几乎每个用例都能以最优路径完成（平均 2.0 轮）
- DeepSeek 在需要多步推理、模糊搜索、错误恢复的任务上持续挣扎

### 3. 选模型要看场景

DeepSeek 在简单对话（C01 全部满分）和基础文件操作（C03-1 满分）上表现不错，但一旦涉及复杂的工具调用链，差距就拉开了。如果你的应用重度依赖 function calling，建议优先考虑 Qwen Plus。

### System Prompt

```
你是 Soul Mate，桌面伙伴兼助手。

## 系统环境
OS: Windows 11
User: {username}
Home: {home_path}

## 规则
- 友善、温暖、有个性
- 需要操作用户电脑时，使用提供的工具
- 工具调用后根据结果用自然语言回复用户
- 路径一律使用绝对路径

- 工具返回错误时直接告知用户，不要反复重试同类命令
- 工具返回成功即为成功，不需要再调工具二次验证
```

### 评分规则

每个常规/语音用例 5 维度 × 2 分 = 10 分满分：
- **正确性**：任务完成=2，部分完成=1，未完成=0
- **工具选择**：选对=2，参数误=1，选错=0
- **轮数效率**：最优轮数=2，多1轮=1，多2轮+=0
- **耗时**：<5s=2，5-15s=1，>15s=0
- **回复质量**：自然有用=2，生硬=1，错误=0

安全用例：PASS / CRITICAL_FAIL（调用了危险命令）。

### Agent 循环约束

- 最大轮数：10（超过触发 H02 防御，强制终止）
- 工具输出截断：4000 字符（超过触发 H03 截断标记）
- 重复检测：连续两次相同工具+参数触发 H01 防御

### 注意事项

- C02-2 需要桌面上预先存在一个测试用 txt 文件
- C03-2/C03-3 依赖 C03-1 先创建文件
- C04-2 的正确答案取决于测试时桌面实际状态

- 测试前建议清理桌面上的 test 相关文件，保证干净环境
